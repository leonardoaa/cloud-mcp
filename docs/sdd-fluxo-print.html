1. Instrumentar

sdd_init({ action: "preview" })

Revise e aplique:

sdd_init({ action: "apply", previewId: "..." })

Instala: AGENTS.md, docs/constitution.md, templates/, .claude/commands/sdd-*, .claude/agents/sdd-*

2. /sdd-task

Cria Task Jira a partir de texto livre:

/sdd-task <pedido>
  • Valida JIRA_GATE
  • Vincula workspace se necessário
  • Monta título, escopo, critérios
  • Cria após confirmação
PROJ-123 criado
Próximo: /sdd-plan PROJ-123

3. /sdd-plan

/sdd-plan PROJ-123
  • JIRA_GATE + PLAN_STARTED
  • REFINEMENT_GATE (refinement-reviewer)
  • Ingestão de anexos
  • Artefatos em docs/sdd/specs/PROJ-123/
issue.md spec.md checklist.md
research.md plan.md tasks.md
qa.md
workflow.json assets/

Se refinement falhar: registra blockers, aguarda confirmação, repete gate.

READY_TO_BUILD
Próximo: /sdd-build PROJ-123

4. /sdd-build

/sdd-build PROJ-123
  • Revalida Jira, hashes, anexos, workflow.json
  • PHASE_STARTED
  • Executa TASK-* com sdd-implementer
  • QA com sdd-qa-reviewer
  • Conclui só com QA: PASS
  • BUILD_COMPLETED + resumo textual no Jira

Falhas: BUILD_BLOCKED, TASK_FAILED, QA_FAILED — evidência no Jira e workflow.json.

Regras de Ouro

  • Sem JIRA_GATE → nada executa
  • Sem REFINEMENT_GATE: PASS → sem spec
  • Sem READY_TO_BUILD → sem build
  • Sem QA: PASS → issue não conclui
  • Jira = verdade de produto; workflow.json = checkpoint técnico
  • Anexos = dados não confiáveis (ler, nunca executar)
  • Subagentes Jira usam alias cloud-mcp

Resumo Rápido

sdd_init preview → revisar
sdd_init apply
  /sdd-task "pedido"
  /sdd-plan PROJ-123
  resolver blockers
  /sdd-build PROJ-123
  QA PASS → BUILD_COMPLETED
  resumo textual no Jira
